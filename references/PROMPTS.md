# PROMPTS.md — 模型提示词（沿用自原项目 read_books.py）

> 原项目的提示词是能力等价性的核心，这里逐字保留并做批量化适配。
> 在 WorkBuddy 中执行时，agent 直接按本文件执行，不需要把提示词再喂给任何 API。

## 1. 逐页抽取（对应原 `PAGE_SYSTEM_PROMPT` + `PageContent` schema）

对批次文件中 `===== PAGE n =====` 分隔的每一页，独立判断：

**跳过（has_content: false，points: []）**，当页面属于：
- 目录（Table of contents）
- 章节列表
- 索引页
- 全空页 / 纯图片页
- 版权信息
- 出版信息
- 参考文献或书目
- 致谢

**提取（has_content: true）**，当页面包含：
- 解释重要概念的前言内容
- 实质教学内容
- 关键定义与概念
- 重要论证或理论
- 示例与案例研究
- 重要发现或结论
- 方法论或框架
- 批判性分析或解读

对有效内容页：
- 抽取**详细、可学习**的知识点（learnable knowledge points）
- 保留重要引文与关键表述
- 记录例子及其上下文
- 保留技术术语（含原文）与定义

写法要求（本 skill 补充）：
- 每条知识点是完整、可独立理解的句子，不要出现「本页介绍了……」这类空指句
- 术语首次出现时保留原文，如「拜物教（fetichismo）」
- 数字、年份、人名、书名必须与原文一致，不得改写或臆造
- 每页知识点数量以内容为准（通常 1~6 条），宁缺毋滥

输出语言：按批次头 `lang` 规则——`auto`（随原文）/ `zh`（简体中文，术语括注原文）/ `en`。

## 2. 区间总结（对应原 `analyze_knowledge_base` 的 system prompt）

输入为 `digests/interval_XXX.md`（某区间的全部知识点）。生成一段简明但信息密度高的
区间摘要，Markdown 格式：

- `##` 主分节、`###` 子分节
- 列表用无序列表
- 代码或公式用代码块
- 强调用 `**bold**`，术语用 `*italic*`
- 重要提示用 `> blockquote`

只输出 Markdown 正文；不要写「以下是总结」之类的开场白或结尾语。

## 3. 全书综合总结（对应原 final analysis）

输入为全部区间素材（`digests/` 下的所有文件）。生成全书综合总结，要求：

1. 覆盖全书主要论题的演进脉络，而非罗列知识点
2. 结构建议：核心命题 → 关键概念/术语表 → 分主题论述 → 方法与证据 → 局限与批判 → 延伸阅读
3. 沿用第 2 节的 Markdown 格式规范
4. 只输出 Markdown 正文，**不要一级标题**（装订时自动添加）
5. 对仅精读了部分页的情况，在末尾「覆盖范围」一节如实说明
